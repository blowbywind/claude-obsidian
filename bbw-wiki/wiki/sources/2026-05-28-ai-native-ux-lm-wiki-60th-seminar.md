## 요약
유훈식 교수(서울 미디어 대학원대학교)가 AI 네이티브 UX/UI 디자인 시스템을 6단계 워크플로우로 정리한 세미나. 핵심은 마크다운 기반 LM 위키 구축 → 에이전트에게 UX 리서치·디자인·코딩을 위임하는 시스템화이다. 마크다운의 토큰 85% 절감(HTML 대비), 35% 빠른 처리 속도가 AI 네이티브 UX의 경제적 근거로 제시됨.

## 핵심 주장
- AI 임베디드(단순 적용)와 AI 네이티브(시스템 재설계)는 본질적으로 다르다
- 노션 AX 4단계: 2단계(비서)→3단계(팀원) 전환이 어렵다 — 시스템 재설계 필요
- LM 위키가 AI 네이티브 UX 시스템의 파운데이션
- 마크다운: HTML 대비 토큰 **85% 절감**, 처리 속도 **35% 향상** — AI 직원 비용·속도 최적화의 핵심
- 사용자 데이터를 마크다운으로 10년 누적 → 조사 없이 합성 사용자로 인사이트 도출 가능
- "회사가 하나의 미니 AI가 돼야 한다" — Jack Dorsey (Block)

## AI 임베디드 vs AI 네이티브

| 구분 | AI 임베디드 | AI 네이티브 |
|---|---|---|
| 접근 방식 | AI를 기존 시스템에 적용 | 조직·시스템 자체를 AI 중심으로 재설계 |
| 전환 난이도 | 쉬움 (개인 단위 가능) | 어려움 (시스템 전체 재설계 필요) |
| 사례 | AI 구독 제공, 개인 사용 장려 | Jack Dorsey의 Block, Elon Musk의 MicroHard |
| 인력 구조 | 기존 조직 유지 | 1인당 에이전트 20–100개 운영, 최소 인력 |

## 노션 AX 4단계 전환 모델

1. **도구**: AI를 개인 도구로 사용
2. **비서**: 회사 구독 제공, AI가 개인 비서 역할
3. **팀원**: AI가 팀원으로 자리잡음 → **시스템 재설계 필요** (2→3 전환이 가장 어려운 구간)
4. **AI 시스템**: MicroHard형 — 전사가 AI 중심 미니 AGI로 운영

## 6단계 AI 네이티브 UX 워크플로우

1. **LM 위키 구축** — 지식 기반 시스템 파운데이션 (가장 중요)
2. **바이브 리서치** — AI로 사용자 조사·분석
3. **바이브 디자인** — AI로 디자인 컨셉·시각적 언어 생성
4. **GI 소스** — Generative Intelligence 디자인 소스 개발
5. **바이브 코딩** — AI로 UI 코드 생성
6. **에이전틱 엔지니어링** — 에이전트 자율 업데이트·유지

## LM 위키 × 옵시디언 실무 세팅

### 성능 수치
- 마크다운: HTML 대비 토큰 **85% 절감**, 처리 속도 **35% 향상**
- Andrej Karpathy가 정의한 LM 위키: LLM + IDE(Obsidian) + Wiki(Markdown)

### VS Code 연동 방법
1. VS Code에서 옵시디언 볼트 폴더 오픈
2. Claude + Codex 플러그인 설치
3. LM이 폴더 내 파일 읽기/쓰기 권한 부여
4. 모델 교체 자유: Claude ↔ Codex 5.5 등

### 팀 공유 방법
- 옵시디언 유료 구독 → 폴더 공유 (가장 편리)
- Git 연동 → 자동 파일 공유
- Google Drive 연동 (가능하지만 비추천)

## 실무 시연: AI 네이티브 UX 리서치 파이프라인

1. **사용자 인터뷰 데이터** → 마크다운 저장 (8명, 김지수·이준혁·박소연 등)
2. **사용자 조사 보고서** 자동 생성 → 마크다운 저장
3. **페르소나 문서** 생성 (Primary/Secondary — 데이터 기반)
4. **합성 사용자(Synthetic User)** — 실제 데이터 기반 + Gemini API → 실시간 대화
5. **시나리오 보드** + 이미지 생성 (Gemini API 통합)
6. **PRD 문서** → 바이브 코딩으로 HTML 바로 생성

### 합성 사용자의 가치
> "사용자 데이터를 마크다운으로 10년치 누적하면 어마어마한 데이터 자산이 된다. 어느 정도 데이터가 쌓이면 조사에 덜 나가도 합성 사용자한테 의견을 물어보면서 기획이 가능하다."

## 디자인 MD / 스킬 MD 표준화

- **디자인 MD**: 색상·타이포·간격 정의 파일 (스티치에서 Visual, Theme, Color, Typography, Component, Layout, Depth 표준화)
- **스킬 MD**: UX 방법론 마크다운 문서 (엠파시 맵, 페르소나, 인터뷰 가이드, 사용성 평가 프로토콜 등)
- 스킬 문서를 축적할수록 에이전트가 UX 전문가로 성장

## 인용

> "이게 결국 사람이 읽기에는 잘 만들어진 문서가 편한데, 마크다운은 AI가 읽기 편한 문서다."

> "AI 에이전트들이 더 빠르고 더 저비용으로 일할 수 있도록 마크다운 형태로 모든 문서를 구성해 나가는게 중요하다."

> "LM 위키가 구축이 되면은 굉장히 쉬워져요. 리서치 데이터도 분석도, 디자인 컨셉도, 디자인 소스도 개발하고 바이브 코딩으로 UI 코드도 — 이 모든게 가능하다."
