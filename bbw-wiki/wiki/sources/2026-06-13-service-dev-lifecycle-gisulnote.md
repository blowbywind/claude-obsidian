## 요약

서비스 기획→설계→개발→테스트→배포→출시→운영까지 전 과정을 실무 경험 기반으로 압축 설명. 개발자 및 PM 경력 20년의 저자가 바이브코딩으로 결과물을 만든 후 다음 단계가 막막한 사람을 위해 전체 흐름을 정리한 강의.

## 핵심 주장

### 1. 기획 (Planning)

**MVP(Minimum Viable Product)**:
- 카카오톡도 당근마켓도 처음엔 가장 단순한 핵심 기능 하나로 시작
- 기획 단계의 핵심은 "기능을 추가"가 아니라 "욕심을 내려놓는 것"
- 카카오톡 MVP = 대화 기능, 당근마켓 MVP = 중고 거래

**타겟 유저 / 페르소나**:
- 누구를 위한 서비스인지 구체적이고 명확할수록 성공 가능성 높음
- 넓은 타겟 = 실제로는 아무도 쓰지 않는 서비스

**기획 구성 요소**:
- 아이디어(생각) → 핵심 기능 도출 → 경쟁 서비스 분석 → 차별화 전략
- 노트에 직접 손으로 그리는 것도 기획의 일종

### 2. 설계 (Design/Architecture)

**화면 설계 (UI/UX)**:
- 사용자가 쓸 화면의 순서·흐름을 구체화
- 사용자 시나리오: 일반 사용자 / 어드민 / 비로그인 사용자별 흐름
- UX = 쉽게 서비스를 제공하기 위한 충분한 고민

**데이터 설계 (ERD)**:
- 회원 / 상품 / 결제 내역 등 테이블 정의
- 테이블 간 관계를 표현한 것이 ERD(Entity-Relationship Diagram)
- 예: 회원 테이블 = 아이디, 패스워드, 이메일, 주소 컬럼

**API 설계**:
- 앱·웹은 DB에 직접 접속 불가 → API 서버가 중간자 역할
- 기능 단위로 API 정의: 회원 가입 API, 상품 등록 API 등
- API ↔ DB 테이블 간 밀접한 연관 관계

### 3. 개발 (Development)

**프론트엔드**:
- 웹: HTML + CSS + JavaScript
- 앱: Android(Android), iOS(Swift/Objective-C)
- 반응형 웹: PC 화면이 모바일 브라우저에서 자동으로 맞춰짐
- 역할: 화면 렌더링, 이벤트 처리, 서버 API 호출

**백엔드**:
- API 개발 (종류별: 회원·상품·결제 등)
- CRUD: Create(생성) / Read(읽기) / Update(수정) / Delete(삭제) — 데이터 처리의 기본
- 예외 처리, 비즈니스 로직 구현

**DB 구축**:
- DBMS 설치: MySQL, Oracle, MongoDB 등
- 테이블 생성 + SQL로 데이터 CRUD

**프론트엔드 ↔ 백엔드 연동**:
- API 호출 테스트 (응답 확인)
- 소셜 로그인 구현

**소스 관리 — Git**:
- 개발자 취업 시 필수 숙지
- **브랜치 전략**: 개발 브랜치(dev) / 운영 브랜치(main) 분리
- 운영 소스에 직접 수정 금지 — 개발 완료·테스트 통과 후 반영

**빌드**:
- 소스 코드 → 실행 가능한 형태 (JAR, 빌드 결과물)
- Node.js: 소스 자체 실행 / React: 빌드 후 배포

### 4. 테스트 (Testing)

| 테스트 종류 | 목적 |
|------------|------|
| 단위 테스트 | 개별 함수/모듈 동작 검증 |
| 통합 테스트 | 컴포넌트 간 연동 검증 |
| 성능 테스트 | 부하 상황 대응력 확인 |
| 보안 테스트 | 취약점 점검 |
| 설치 테스트 | 배포 환경 정상 동작 확인 |

### 5. 배포 (Deployment)

**클라우드 선택**:
| 상황 | 추천 |
|------|------|
| 단순 웹 서비스 | Vercel, Cloudflare Pages 등 |
| DB·API 규모가 큰 서비스 | AWS / Azure / GCP |

**배포 과정**:
1. 소스 빌드 결과물 → 서버에 업로드(deploy)
2. 서버에서 프로그램 실행 (웹: 포트 80, WAS: 포트 8080)
3. 도메인 구매 → IP에 연결 (도메인 없이는 외부 접속 불가)
4. SSL 인증서 설치 → HTTPS 설정 (필수)

**앱 출시 (추가)**:
- 앱스토어(iOS) / 구글 플레이(Android) 계정 가입 → 앱 정보 입력 → 결과물 업로드 → 심사 → 스토어 노출 (수일 소요)

### 6. 운영/유지보수 (Operations)

- **장애 대응**: 문제 발생 시 신속 복구
- **기능 추가·개선**: 출시는 시작일 뿐, 지속적 업데이트
- **Git 기반 코드 관리**: 수정·추가 반복
- **수익화**: 기획 단계부터 함께 고민해야 함 — 나중에 붙이면 서비스 구조 전체가 흔들릴 수 있음

### 저자 배경 (맥락)

- 개발자 + 개발 팀장: 중소기업 10년
- 프로젝트 매니저 + 아키텍트: 대기업 10년
- 외국계 컨설팅: 시스템 구축·컨설팅
- 스타트업 10개+ 서비스 기획~운영 경험
