## 요약

컴퓨터 구조(폰노이만)부터 프로그램이 프로세스가 되어 CPU에서 실행되는 흐름까지 한 장의 다이어그램으로 설명하는 입문 강의 1부. 컴파일 언어 vs 인터프리터 언어 구분, 메모리 계층 구조, 시분할 스케줄링까지 다룬다. 2부에서 메모리 교체 기법·CPU 스케줄링·프로세스/스레드를 다룰 예정.

## 핵심 주장

### 1. 컴퓨터 구조 — 폰노이만 아키텍처

```
[CPU] ←버스→ [메모리] ←버스→ [디스크]
  ↕
[I/O 장치]
  입력: 키보드, 마우스
  출력: 모니터, 프린터
```

- **CPU**: 연산 처리 장치 (프로세서)
- **메모리(RAM)**: 빠르고 비싼 임시 저장소 — 실행할 명령어를 CPU에 공급
- **디스크**: 느리고 싼 영구 저장소 — 프로그램과 데이터 보관
- **버스**: CPU↔메모리↔디스크 사이 데이터를 실어 나르는 통로
- 폰노이만이 제시한 이 구조가 현대 컴퓨터의 근간

### 2. 프로그램이란

**고급 언어**(사람이 읽기 쉬운 문법) → **컴파일/인터프리팅** → 실행 가능한 형태

| 분류 | 언어 | 실행 방식 |
|------|------|---------|
| **컴파일 언어** | C, C++, Java | 소스 코드 전체를 기계어(또는 바이트코드)로 변환 후 실행 |
| **인터프리터 언어** | JavaScript, Python | 소스 코드를 한 줄씩 해석하며 즉시 실행 |

- **C/C++**: 컴파일 → `.exe` (기계어) 생성
- **Java**: 컴파일 → `.class` (바이트코드) → JVM이 실행
- **JavaScript**: 브라우저 내장 인터프리터 엔진이 실행 (V8 등)
- **Python**: 파이썬 인터프리터가 실행

> 웹 브라우저가 URL 요청 시: 서버 → HTML/CSS/JS 내려줌 → 브라우저가 JS 인터프리터로 실행

### 3. 프로그램 → 프로세스 실행 흐름

```
[디스크] 프로그램 파일 저장
    ↓ 더블클릭(실행)
[메모리] 프로그램의 일부 로드
    ↓
[CPU] 메모리의 명령어들 실행
```

- **프로그램**: 디스크에 저장된 실행 파일 (정적)
- **프로세스**: 실행 중인 프로그램 (동적, 메모리에 올라간 상태)
- "프로그램의 일부"만 메모리에 올라오는 이유 → 메모리 계층 구조

### 4. 메모리 계층 구조

| | 디스크 | 메모리(RAM) |
|--|--------|-----------|
| 속도 | 느림 | 매우 빠름 |
| 단가(용량당) | 저렴 | 비쌈 |
| 역할 | 영구 저장 | CPU에 빠르게 명령어 공급 |

**비유**: 디스크=책장, 메모리=책상 위 책꽂이 (자주 쓸 책만 꺼내 놓음)

메모리는 용량이 한정되어 있으므로 프로그램 전체가 아닌 **지금 실행에 필요한 부분만** 올린다.

### 5. 시분할(Time-sharing) — 동시 실행의 원리

여러 프로그램이 동시에 실행되는 것처럼 보이는 이유:

```
CPU → 프로세스A 실행 → 프로세스B 실행 → 프로세스C 실행 → 프로세스A ...
      (1ms 미만 단위로 초고속 교체)
```

- CPU는 하나지만 극도로 빠른 속도로 여러 프로세스를 **번갈아** 실행
- 전환 속도가 너무 빨라 사용자 눈에는 동시 실행으로 보임
- 메모리에는 여러 프로세스의 일부가 동시에 올라와 있음

### 6. 메모리 교체 기법 (이 영상에서 예고)

메모리가 꽉 찬 상태에서 현재 메모리에 없는 프로그램 영역이 필요할 때 → 기존 영역을 내보내고 새 영역을 올리는 교체 발생. 2부에서 상세 설명 예정.
