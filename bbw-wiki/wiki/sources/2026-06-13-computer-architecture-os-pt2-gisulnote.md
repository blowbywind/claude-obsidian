## 요약

컴퓨터구조·OS 시리즈 2부. 1부에서 예고한 메모리 교체 기법·디스크 스케줄링·CPU 스케줄링을 다루고, 프로세스 vs 스레드 차이와 컨텍스트 스위칭·스레싱까지 설명하는 마무리 강의.

## 핵심 주장

### 1. 메모리 교체 기법 (Page Replacement Algorithms)

메모리가 꽉 찼을 때 어떤 페이지를 내보낼지 결정하는 알고리즘.

| 기법 | 풀네임 | 교체 기준 |
|------|--------|---------|
| **FIFO** | First In, First Out | 먼저 들어온 페이지 먼저 교체 |
| **LRU** | Least Recently Used | 최근에 가장 적게 사용된 페이지 교체 |
| **LFU** | Least Frequently Used | 사용 빈도가 가장 낮은 페이지 교체 |
| **NRU** | Not Recently Used | 최근에 사용되지 않은 페이지 교체 |
| **OPT** | Optimal | 미래에 가장 오래 안 쓰일 페이지 교체 (이상적, 현실 구현 불가) |

### 2. 메모리 계층 구조 (전체)

```
[레지스터]        ← CPU 내부, 극소용량, 극고속, 다음 명령어 대기
[캐시 메모리]     ← 자주 쓰는 데이터 예비 저장
[메인 메모리(RAM)]← 실행 중인 프로그램 데이터
[가상 메모리]     ← 디스크 일부를 RAM처럼 사용 (페이지 단위 교체)
[디스크]          ← 영구 저장, 최저속
```

**가상 메모리**: RAM 용량 부족 시 디스크 일부를 메모리처럼 활용. 페이지(Page) 단위로 올리고 내리며 교체. 페이지 파일(Page File)이라고도 함.

### 3. 디스크 스케줄링

HDD 실린더 구조에서 데이터를 빠르게 찾는 알고리즘.

| 기법 | 설명 |
|------|------|
| **FCFS** | First Come, First Served — 요청 순서대로 처리 |
| **SSTF** | Shortest Seek Time First — 현재 헤드 위치에서 가장 가까운 것 먼저 |
| **SCAN** | 헤드가 한 방향으로 쭉 이동하며 처리 (엘리베이터 알고리즘) |

### 4. CPU 명령어 집합 구조

| 구분 | 풀네임 | 특징 |
|------|--------|------|
| **CISC** | Complex Instruction Set Computer | 복잡한 명령어 하나에 여러 연산 포함 |
| **RISC** | Reduced Instruction Set Computer | 단순한 명령어로 쪼개서 처리, 고성능 |
| **EPIC** | Explicitly Parallel Instruction Computing | 병렬 처리 명시 |

### 5. CPU 스케줄링

어떤 프로세스(일)을 CPU가 먼저 처리할지 결정하는 방식.

**비유**: 복사집(CPU) 앞에 줄 선 손님들(프로세스) — 어떤 순서로 처리할지

**비선점형 스케줄링** (실행 중 강제 중단 불가):
| 기법 | 설명 |
|------|------|
| FCFS | 먼저 온 순서대로 처리 (책 한 권 전체 복사 중엔 뒤 사람 계속 대기) |
| SJF | 처리 시간 짧은 것 먼저 (한 장짜리 먼저 처리) |

**선점형 스케줄링** (우선순위 높은 작업이 끼어들 수 있음):
| 기법 | 설명 |
|------|------|
| **라운드 로빈** | 각 프로세스에 동일 시간 할당, 돌아가며 처리 → OS 실제 사용 방식 |
| SRTF | 남은 처리 시간이 짧은 것 먼저 |
| 다단계 큐 | 우선순위별 복수 큐 운영 |

> 라운드 로빈이 운영체제에서 실제로 사용하는 핵심 방식. 시분할(Time-sharing)의 구현체.

### 6. 운영체제(OS) 역할 종합

| OS 관리 영역 | 주요 작업 |
|-------------|---------|
| **CPU 관리** | 스케줄링 (어떤 프로세스에 CPU를 줄지) |
| **메모리 관리** | 페이지 교체, 가상 메모리 운영 |
| **디스크 관리** | 파일 시스템, 스케줄링 |
| **I/O 관리** | 입출력 장치 제어 |
| **프로세스 관리** | 프로세스 생성·종료·동기화 |

컴퓨터 구조(하드웨어) = CPU + 메모리 + 디스크 + I/O  
운영체제(소프트웨어) = 그 하드웨어를 관리하고 프로그램을 실행시키는 주체

### 7. 프로세스 vs 스레드

```
[멀티프로세스]
  프로세스 A (프로그램 단위)
    ├─ 스레드 1 (일 처리 단위)
    ├─ 스레드 2
    └─ 스레드 3
  프로세스 B
  프로세스 C
```

| 구분 | 설명 |
|------|------|
| **프로세스** | 실행 중인 프로그램 (독립된 메모리 공간) |
| **스레드** | 프로세스 내 일을 처리하는 단위 (메모리 공유) |
| **멀티스레드** | 한 프로세스 내 여러 스레드로 동시성 구현 |

**예시 — 카카오톡**:
- 스레드 1: 화면 표시 + 타이핑 입력 처리
- 스레드 2: 네트워크 통신 (메시지 수신)
- → 내가 타이핑하는 동안 상대방 메시지가 들어오는 것이 멀티스레드 동작

스레드도 실제로는 순차 실행이나, 코어가 여러 개면 진짜 병렬 가능.

### 8. 컨텍스트 스위칭 & 스레싱

**컨텍스트(Context)**: 스레드/프로세스 실행에 필요한 환경 정보(변수 등)

**컨텍스트 스위칭(Context Switching)**:
- 스레드/프로세스 전환 시 실행 환경 전체를 교체하는 작업
- 전환 비용(오버헤드) 발생

**스레싱(Thrashing)**:
- 컨텍스트 스위칭만 반복되고 실제 실행 시간이 극히 줄어드는 현상
- 원인: 메모리 부족 상태에서 너무 많은 프로세스 실행
- 결과: 컴퓨터 전체 성능 급락
