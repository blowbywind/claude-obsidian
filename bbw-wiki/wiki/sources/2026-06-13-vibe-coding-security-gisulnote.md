## 요약

바이브코딩(AI 코딩)으로 만든 웹사이트를 배포하기 전에 반드시 점검해야 하는 보안 항목 소개. OWASP Top 10 기반으로 URL만 입력하면 자동 보안 스캔하는 도구를 제공. AI를 활용한 보안 보완 워크플로우 제시.

## 핵심 주장

### 1. 보안 점검이 필요한 구간

| 구간 | 내용 | 바이브코딩(PaaS 배포) 시 책임 |
|------|------|---------------------------|
| **네트워크 보안** | 데이터 스누핑 방지 → HTTPS 적용 | 플랫폼 제공 (Vercel 등) |
| **서버 보안** | 해킹 대비 보안 패치·솔루션 설치 | 플랫폼 제공 |
| **DB 보안** | 패스워드 평문 저장 금지, 개인정보 암호화 | 플랫폼 제공 (단, 소스 로직은 개발자 책임) |
| **소스 코드 보안** | XSS, 인젝션 등 코드 취약점 | **개발자(바이브코더) 책임** |

→ PaaS(Vercel/Cloudflare 등)로 배포하면 인프라 보안은 플랫폼이 담당,
  **소스 코드에서 발생하는 취약점은 개발자가 직접 점검해야 한다.**

### 2. OWASP Top 10

OWASP(Open Web Application Security Project)가 매년 발표하는 웹 보안 10대 취약점.

| 항목 | 설명 |
|------|------|
| **접근 제어 실패** | 권한 없는 사용자가 다른 사람 데이터·기능에 접근 |
| **암호화 실패** | 패스워드·개인정보 평문 저장 또는 취약한 암호화 |
| **인젝션** | SQL·명령어 인젝션, 악성 쿼리 실행 |
| **인시큐어 디자인** | 보안이 고려되지 않은 설계 단계의 문제 |
| **보안 설정 오류** | 기본 설정 그대로 사용, 불필요한 기능 노출 |
| **취약한 컴포넌트** | 라이브러리·패키지에 백도어·취약점 포함 |
| **인증 실패** | 세션·토큰 관리 미흡 |
| **무결성 오류** | CI/CD 파이프라인·업데이트 검증 부재 |
| **보안 로깅 부족** | 침해 탐지를 위한 로그 부재 |
| **정보 노출** | 서버 에러·설정 파일 외부 노출 |

### 3. URL 기반 자동 보안 스캔

- URL 입력 → OWASP Top 10 기준 자동 점검
- 탐지 예시: CSP(Content Security Policy) 헤더 누락, WordPress 설정 노출 등
- 탐지 결과를 AI에게 붙여넣어 보완 요청 → 코드 수정 반복

### 4. 바이브코더를 위한 보안 점검 워크플로우

```
1. URL 스캔 도구로 현재 서비스 점검
2. 위험 항목 목록 복사
3. AI(Claude 등)에 "이 항목들을 내 코드에서 점검하고 보완해줘" 요청
4. 수정된 코드 재배포
5. 재스캔으로 보완 확인
```

핵심: "단순히 보안 점검해줘"보다 **OWASP 항목별로 구체적으로** 전달해야 AI가 정확히 수정함.
