## 요약

Anthropic 공식 블로그의 하네스 실험 결과를 8분 36초로 압축 해설한 영상. 같은 Claude 모델, 같은 태스크("레트로 게임 만들어줘")에서 **$9(고장) vs $200(완동)** 차이를 만든 유일한 변수가 에이전트 구조였음을 보여준다. Planner-Generator-Evaluator 3에이전트 구조의 원리와 적용 방법을 실험 데이터와 함께 설명한다.

## 핵심 주장

- AI 결과물 품질 차이의 원인은 모델이 아닌 **구조**다
- 모델이 좋아질수록 구조 설계 능력의 가치는 더 올라간다
- "구조의 한계와 필요성은 사라지지 않고, 더 높은 수준으로 이동한다"

## 핵심 내용

### AI 자체의 두 가지 근본 문제

**1. 컨텍스트 불안 (Context Anxiety)**
- 대화가 길어질수록 AI가 지친다
- 초반에는 꼼꼼하게 일하다가, 맥락이 쌓이면 대충 마무리
- "할 일이 남아있는데 이 정도면 됐습니다"라고 선 정리
- 야근이 길어지면 직원이 퇴근 직전 보고서를 슬쩍 넘기는 것과 동일

**2. 자기 평가 편향 (Self-Evaluation Bias)**
- AI가 자신이 만든 것을 스스로 평가하면 항상 잘했다고 판단
- 실제로 게임플레이가 안 되는 결과물에도 "완성됐습니다"라고 보고
- 거울 속 자기 모습처럼 자기 실수가 안 보임

### 실험 1: 웹 디자인 (2에이전트)

- **구조**: Generator(제작) + Evaluator(평가, 4가지 기준)
- **평가 기준**: 디자인 품질, 독창성, 완성도, 기능성
- **Evaluator 도구**: 실제 웹사이트를 클릭·스크롤·버튼 조작 가능
- **반복**: 최대 15회
- **결과**: 네덜란드 미술관 웹사이트
  - 1~9회: 예상 가능한 깔끔한 디자인
  - **10회차**: AI가 스스로 방향을 틀어 CSS 3D 공간으로 전환
    - 체크무늬 바닥, 그림 걸기, 문으로 다른 갤러리 이동
    - 스크롤이 아닌 "미술관 안을 걸어다니는" 경험
    - Anthropic도 예상 못 했던 결과

### 실험 2: 레트로 게임 앱 (3에이전트)

**구조: Planner + Generator + Evaluator**

| 에이전트 | 역할 | 핵심 원칙 |
|---------|------|---------|
| Planner | 1줄 요청 → 전체 스펙 | **WHAT만 결정, HOW는 위임** |
| Generator | 스프린트 단위 기능 개발 | 기능 하나씩 순차 빌드 |
| Evaluator | 실제 앱 테스트 + 버그 보고 | 스프린트 전 성공 기준 합의 |

**Planner의 역할 예시** ("레트로 게임 만들어줘" →):
- 레벨 에디터 기능 목록
- 스프라이트 에디터 도구 요구사항
- AI 기능 통합 위치 설계
- ※ 기술 구현 방법은 Generator에게 위임 (기획 단계의 기술 오류가 전체에 퍼지는 것 방지)

**Evaluator의 실제 로그 예시**:
> "사각형 채우기 도구가 드래그 영역으로 채워야 한다. 실패했음. 시작점·끝점에서만 타일이 찍히고 가운데가 안 채워진다."

**결과 비교**:
| | $9 버전 | $200 버전 |
|--|--------|---------|
| 외관 | 그럴 듯함 | 완성도 높음 |
| 기능 | 캐릭터 움직이지 않음, 핵심 로직 고장 | 16개 기능 정상 동작 |
| 스프린트 | 없음 | 10개 이상 |
| 포함 기능 | 기본 에디터 2개 | 레벨 에디터, 스프라이트 에디터, 애니메이션 시스템, 사운드 이펙트, AI 스프라이트 생성, AI 레벨 디자이너 |
| 플레이 가능 | ✗ | ✓ |

### 모델 개선 이후 구조 변화

더 좋은 모델 출시 후:
- **사라진 것**: 컨텍스트 불안 해소 → 스프린트 구조 제거. 에이전트 3개 유지하되 단순화
- **유지된 것**: Evaluator (마지막 디테일 버그는 여전히 놓침)

**음악 DAW 예시** (단순화된 구조):
- 입력: 1줄 프롬프트
- 시간: 3시간 50분
- 비용: $124
- 결과: 멜로디·드럼 트랙·믹싱 가능한 프로그램
- Evaluator가 잡은 버그: 오디오 녹음 버튼 미동작, 클립 드래그 이동 불가

### 핵심 인용

> "모델이 좋아져도 한계와 조합의 가능성은 줄어들지 않는다. 이동할 뿐이다." — Anthropic 연구자
>
> 쉬운 등산 코스가 열리면 더 높은 봉우리로 가는 것처럼, 장비의 필요성이 사라지는게 아니라 더 높은 수준에서 필요해진다.

### 개발자에게 주는 함의

- 같은 모델·IDE를 써도 결과물 차이가 극심한 이유: 컨텍스트 설계 여부
- 좋은 방법: 코딩 컨벤션·규칙·기존 패턴을 AI에게 먼저 심어놓고 시작
- 나쁜 방법: "이거 해줘"로 시작 → "우리 팀은 이렇게 안 한다" 수정 루프에 갇힘
- **격차의 본질**: 코딩 실력이 아닌 구조를 설계하는 능력
