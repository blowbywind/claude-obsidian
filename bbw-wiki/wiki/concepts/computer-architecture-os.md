## 정의

컴퓨터 하드웨어가 어떻게 구성되는지(구조)와, 그 위에서 프로그램이 어떻게 실행·관리되는지(운영체제)를 다루는 CS 핵심 영역. 프로그램이 코드에서 CPU 실행까지 이르는 전 흐름을 이해하는 것이 핵심.

## 폰노이만 아키텍처 (현대 컴퓨터의 근간)

```
[CPU] ←─ 버스 ─→ [메모리(RAM)] ←─ 버스 ─→ [디스크]
  ↕
[I/O: 키보드·마우스 / 모니터·프린터]
```

| 구성요소 | 역할 | 특성 |
|---------|------|------|
| **CPU** | 명령어 처리·연산 | 속도 최고, 용량 없음 |
| **메모리(RAM)** | 실행 중 데이터·명령어 임시 저장 | 빠름, 비쌈, 휘발성 |
| **디스크** | 프로그램·데이터 영구 저장 | 느림, 저렴, 비휘발성 |
| **버스** | 구성요소 간 데이터 통로 | — |

## 컴파일 언어 vs 인터프리터 언어

| 구분 | 언어 | 실행 방식 |
|------|------|---------|
| **컴파일** | C, C++, Java | 소스 전체 → 기계어/바이트코드 변환 후 실행 |
| **인터프리터** | JavaScript, Python | 소스 코드 한 줄씩 즉시 해석·실행 |

- Java: 컴파일 → `.class`(바이트코드) → **JVM**이 실행
- JS: 브라우저 내장 **V8** 엔진이 인터프리팅
- Python: **파이썬 인터프리터**가 실행

## 프로그램 → 프로세스 흐름

```
[디스크] 저장된 프로그램 파일
    ↓ 실행(더블클릭)
[메모리] 프로그램의 일부 로드
    ↓
[CPU] 메모리의 명령어 실행
```

- **프로그램**: 디스크의 정적 파일
- **프로세스**: 메모리에 올라와 실행 중인 상태 (동적)

## 메모리 계층 구조

메모리는 빠르지만 비싸고 용량이 작음 → 프로그램 전체가 아닌 **현재 필요한 부분만** 로드

```
[디스크] ← 책장 (많지만 꺼내는 데 시간 걸림)
[메모리] ← 책상 위 책꽂이 (자주 쓸 것만 올려두고 즉시 꺼냄)
[CPU 캐시] ← 손 안에 쥔 페이지 (극소량, 극고속)
```

메모리가 부족하면 **메모리 교체(스와핑/페이징)** 발생 — 지금 안 쓰는 영역을 디스크로 내보내고 필요한 영역을 올림.

## 시분할(Time-sharing) — 멀티태스킹의 원리

CPU 하나가 여러 프로세스를 초고속으로 교체 실행 → 사용자 눈에는 동시 실행처럼 보임

```
CPU: [A] → [B] → [C] → [A] → [B] → ... (ms 미만 단위)
메모리: [A의 일부] [B의 일부] [C의 일부] 동시에 적재
```

## 운영체제(OS)의 역할 (2부 상세 예정)

OS는 하드웨어 위에서 프로그램들이 공평하게, 효율적으로 자원을 쓰도록 관리하는 소프트웨어.

| OS 기능 | 설명 |
|---------|------|
| **프로세스 관리** | 시분할로 여러 프로세스 스케줄링 |
| **메모리 관리** | 교체 기법(페이징·스와핑)으로 한정된 메모리 효율화 |
| **CPU 스케줄링** | 어떤 프로세스에 CPU를 줄지 결정 (Round Robin 등) |
| **디스크 스케줄링** | 디스크 I/O 순서 최적화 |
| **프로세스/스레드 관리** | 동시성 제어 |

## 메모리 교체 기법 (Page Replacement)

메모리가 꽉 찼을 때 어떤 페이지를 내보낼지 결정.

| 기법 | 기준 |
|------|------|
| **FIFO** | 먼저 들어온 것 먼저 교체 |
| **LRU** | 최근에 가장 적게 사용된 것 교체 |
| **LFU** | 사용 빈도가 가장 낮은 것 교체 |
| **OPT** | 미래에 가장 오래 안 쓰일 것 교체 (이상적, 현실 불가) |

**가상 메모리**: 디스크 일부를 RAM처럼 사용. 페이지(Page) 단위 교체. 메모리 용량의 논리적 확장.

**메모리 전체 계층 (빠름 → 느림)**:
```
레지스터 → 캐시 메모리 → 메인 메모리(RAM) → 가상 메모리 → 디스크
```

## CPU 스케줄링

어떤 프로세스에 CPU를 줄지 결정. **복사집 비유**: 복사기=CPU, 줄 선 손님=프로세스.

**비선점형** (실행 중 강제 중단 불가):
- FCFS: 먼저 온 순서대로 (책 한 권 전체 복사 중엔 뒤가 계속 대기)
- SJF: 처리 시간 짧은 것 먼저

**선점형** (우선순위 높은 작업이 끼어들 수 있음):
- **라운드 로빈(Round Robin)**: 동일 시간 할당씩 돌아가며 처리 → OS 실제 사용 방식
- SRTF: 남은 시간 짧은 것 먼저
- 다단계 큐: 우선순위별 복수 큐

> 라운드 로빈이 시분할(Time-sharing)의 실제 구현체.

## CPU 명령어 집합

| 구분 | 특징 |
|------|------|
| **CISC** | 복잡한 명령어 하나에 여러 연산 포함 |
| **RISC** | 단순 명령어로 쪼개서 처리, 고성능 |

## 운영체제(OS) 역할 종합

| 관리 영역 | 주요 작업 |
|----------|---------|
| CPU 관리 | 스케줄링 |
| 메모리 관리 | 페이지 교체, 가상 메모리 |
| 디스크 관리 | 파일 시스템, I/O 스케줄링 |
| 프로세스 관리 | 생성·종료·동기화 |

컴퓨터 구조 = 하드웨어(CPU + 메모리 + 디스크 + I/O)  
운영체제 = 그 하드웨어를 관리하고 프로그램을 실행시키는 소프트웨어

## 프로세스 vs 스레드

```
프로세스 A (프로그램 단위, 독립 메모리)
  ├─ 스레드 1 (일 처리 단위, 메모리 공유)
  ├─ 스레드 2
  └─ 스레드 3
프로세스 B
프로세스 C
```

- **프로세스**: 실행 중인 프로그램. 독립된 메모리 공간.
- **스레드**: 프로세스 내 작업 단위. 같은 메모리 공유.
- **멀티스레드 예시(카카오톡)**: 스레드1=화면+입력, 스레드2=네트워크 수신 → 동시 동작처럼 보임

## 컨텍스트 스위칭 & 스레싱

**컨텍스트(Context)**: 스레드 실행에 필요한 환경 정보(변수, 레지스터 상태 등)

**컨텍스트 스위칭**: 스레드/프로세스 전환 시 실행 환경 전체 교체. 전환 비용(오버헤드) 발생.

**스레싱(Thrashing)**: 컨텍스트 스위칭만 반복되고 실제 실행이 안 되는 현상.
- 원인: 메모리 부족 상태에서 과다 프로세스 실행
- 결과: 컴퓨터 전체 성능 급락
