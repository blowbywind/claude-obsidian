## 정의
인간 1명이 AI 에이전트만으로 구성된 팀을 운영하는 구조. 플랫폼 특성에 따라 역할을 분리하고, 옵시디언 위키로 에이전트 간 맥락을 공유하는 것이 핵심.

## 역할 분리 원칙

| 구분 | 헤르메스 | Claude Code |
|---|---|---|
| 비유 | 에이전시 (외주) | 인하우스 (내부) |
| 시간대 | 야간·상시 | 주간 |
| 특기 | 크론잡·비동기·장기 기억 | 기획·Plan 모드·스킬 제작 |
| 연결 | 텔레그램 모바일 | 터미널 |

분리 이유: "사람들도 폴더가 많아지면 찾기 어려워지는 것처럼, 에이전트들도 집중할 수 있는 환경을 만들어 주기 위해서"

## 김요일의 팀 구성 예시 (10명)

### 헤르메스 에이전트 5명 (린네이티브)

| 에이전트 | 역할 | 야간 학습 |
|---|---|---|
| 효율이 (효1) | 개발 + 취합·보고 (오른팔, 모더레이터) | 실리콘밸리 논문·AI 뉴스·Reddit |
| 효리 (효2) | 디자인 (웹·앱 UI, PPT) | Dribbble 등 UI 레퍼런스 + OpenDesign 실습 |
| 효삼이 (효3) | 자동화 + 개발 검증 | — (Claude Code로 연결, 특이) |
| 효나 (효4) | 콘텐츠 (이미지·영상·SNS) | — |
| 효정이 (효5) | 강의 보조·리서치·일정 관리 | — |

### Claude Code 에이전트 5명 (린 프로젝트)

| 에이전트 | 역할 |
|---|---|
| 시원 (C1) | 오케스트레이터 — Session Send로 팀원에게 지시 후 최종 보고 |
| C2, C3, 신하 | Plan 모드 기획, 스킬 제작, 연결 작업 |

## 에이전트 간 통신 — Session Send

**= Claude Code Agent Teams** (v2.1.80+ 공식 지원):
- 리드(C1)가 팀원 에이전트에게 업무 지시 → 각자 독립 컨텍스트에서 작업 → 결과 리드에게 보고
- 통신 방식: **공유 파일(디스크) 기반** 읽기/쓰기
- Direct Message(1:1) + Broadcast(전체) 모두 지원
- 팀원은 CLAUDE.md, MCP, Skills 자동 로드

## 맥락 공유 — 옵시디언 위키

10명 에이전트가 **동일 옵시디언 위키 공유** → 도구 종속성 제거:
> "코덱스든 클로드 코드든 제미나이든 어떤 도구를 사용하든 이 위키만 있으면 하던 작업을 바로 이어서 진행할 수 있고, 일일이 업무에 대해 설명을 할 필요가 없어집니다."

## 실제 작업물 예시

**유튜브 쇼츠 조회수 급상승 실시간 수집 사이트**:
- 효리(UI) → 효1(개발) → 효3(검증) → 효나(데이터) + 김요일(기획·감독)
- 향후: 크론잡으로 자가 점검·수정, UX 리서치 자동화 후 효리에게 전달 → 디자인 수정

## AI 네이티브 ERP 구상

옵시디언 위키를 ERP에 통합하면 전 직원이 AI 에이전트를 보조 직원으로 활용:

| 기능 | 내용 |
|---|---|
| 대시보드 | 전체 업무 한 눈에 |
| 태스크 뷰 | 세부 일정 확인 |
| 메신저 | 직원 + 에이전트 통합 대화 |
| 에이전트 현황 | 예약 작업 모니터링 |
| 채널 연결 | 외부 흐름 원클릭 연결 |
| 스킬 인벤토리 | 사용 가능한 스킬·플러그인 목록 |
| 토큰 대시보드 | 작업별 토큰 사용량 분석 |

## AI 임베디드 vs AI 네이티브 (유훈식 교수 정의)

| 구분 | AI 임베디드 | AI 네이티브 |
|---|---|---|
| 접근 | AI를 기존 조직에 적용 | 조직 구조를 AI 중심으로 재설계 |
| 전환 | 쉬움 (개인 단위 가능) | 어려움 (시스템 재설계 필요) |
| 인력 | 기존 조직 유지 | 1인당 에이전트 20–100개, 최소 인력 |
| 사례 | — | Jack Dorsey의 Block, Elon Musk의 MicroHard |

**노션 AX 4단계**: 도구 → 비서 → **팀원(3단계 — 재설계 필요)** → AI 시스템
