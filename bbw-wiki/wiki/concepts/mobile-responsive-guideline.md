# 모바일 반응형 웹 UI/UX 최적화 가이드라인

> 모바일 기기 및 다양한 뷰포트 환경에서 모바일 사용성과 접근성을 확보하기 위한 디자인 및 구현 원칙 가이드라인.

---

## 1. 2-Panel 및 다단 레이아웃 대응 전략
* **문제점**: 모바일 화면에서 데스크톱용 좌/우 2-Panel 구조를 그대로 노출하거나 세로로 단순히 쌓아버릴 경우, 정보의 중요도 왜곡 및 불필요한 이중 스크롤이 유발됨.
* **해결책**:
  - 모바일(768px 미만) 뷰포트에서는 좌(Roster/목록)와 우(Detail/상세) 영역을 상태 변수(예: `showDetail`)에 따라 토글 분기 처리하여 **단일 화면 구조**로 전환한다.
  - 상세 화면으로 이동했을 시 목록으로 즉시 복귀할 수 있는 **뒤로가기 네비게이션**(`ChevronLeft` 등)을 상단 또는 가장자리에 확실히 배치한다.

## 2. 중첩된 뷰포트 높이(dvh/vh) 방지 및 스크롤바 확보
* **문제점**: Next.js Layout 등에서 이미 `h-dvh` 및 `overflow-hidden`을 준 구조 내부에서 페이지 컴포넌트가 다시 `h-dvh`를 중첩 선언하면, 모바일 브라우저 주소창이나 스크롤바 높이 계산 오차로 인해 하단 영역이 화면 밖으로 잘리고 스크롤되지 않는 현상이 발생함.
* **해결책**:
  - 레이아웃이 화면 크기를 고정하고 있는 경우, 하위 페이지의 높이는 `h-full min-h-0`으로 위임하여 부모 플렉스박스 제약 안에서 유연하게 영역을 잡도록 유도한다.
  - 스크롤이 일어나야 하는 리스트 컨테이너에는 `overflow-y-auto`와 `min-h-0`을 강제하여 브라우저 스크롤 메커니즘이 안전하게 작동하도록 보장한다.

## 3. 가로 텍스트 세로 꺾임(Text Wrapping) 예방
* **문제점**: 모바일 기기의 극도로 좁은 가로 폭(320px~375px)에서 긴 텍스트(봇 이름, 태스크 요약, 타임스탬프 등)나 인라인 칩 내부 텍스트가 줄바꿈되어 글자가 한 자씩 아래로 흘러 세로로 보이는 현상이 발생함.
* **해결책**:
  - 단어 분리가 일어나지 않고 가로 흐름을 지켜야 하는 텍스트에는 `whitespace-nowrap`과 `truncate`를 조합 적용한다.
  - 다중 정보(예: 봇 이름, 작업 상세, 상태 뱃지, 시작 시간)가 모여 있는 리스트 항목은 모바일에서 `flex-col`로 분기하여 위아래 2열 구조로 재정렬하고, 태블릿 이상에서만 `flex-row` 한 줄 구조로 표시되도록 분기 마크업을 구축한다.
  - 가로 폭을 많이 사용하는 탭이나 카테고리 선택기는 강제로 줄바꿈하여 아래로 내리는 대신, `flex-nowrap overflow-x-auto`를 설정해 모바일에서 손가락 터치로 **가로 스크롤**할 수 있도록 구현한다.

## 4. 터치 디바이스 모달 및 입력창 UI 설계
* **문제점**: 모바일에서 텍스트를 입력하기 위해 가상 소프트 키보드가 올라올 때, 모달 영역의 높이가 화면 높이를 초과하게 되면 하단에 위치한 '전송' 또는 '생성' 버튼이 화면 아래로 묻혀 터치 불가능해짐.
* **해결책**:
  - 모바일 모달 창에는 `max-h-[90vh] overflow-y-auto`를 강제하여 모달 내부에서 개별 스크롤이 작동하도록 제어한다.
  - 채팅 입력창(`textarea`)은 글자 입력량에 따라 무한히 늘어나 본문을 가리지 않도록, 모바일 환경에서는 최대 높이(`max-h`)를 `96px`(데스크톱의 약 60%) 내외로 타이트하게 차단하고 스크롤바가 안에서 롤링되게 조절한다.

## 5. 터치 타깃 영역과 상호작용 피드백 (WCAG 2.2 AA)
* **문제점**: 마우스 호버에만 의존하는 툴팁이나 설명창은 터치 기기에서 먹통이 되거나, 칩 내부의 X(삭제) 버튼 등 터치 타깃의 크기가 너무 작아 오작동이 자주 생김.
* **해결책**:
  - 모든 상호작용성 요소(버튼, 링크, 토글 칩 등)는 WCAG 2.2 SC 2.5.8 기준 최소 **24x24 CSS px** 크기의 터치 바운더리를 충족해야 한다.
  - 드래그나 호버 전용 기능이 있을 시에는 반드시 단순 클릭/터치 방식의 대안 인터랙션(예: 클릭 시 옵션 메뉴 팝오버 노출)을 함께 병행 구현한다.

## 6. 모바일 공간 낭비 방지를 위한 StatCard 및 메타 정보 최적화
* **문제점**:
  - 통계 데이터(예: 전체 에이전트, 활성 개수 등)를 표현하는 `StatCard` 그리드가 모바일 뷰포트에서 `grid-cols-2` 등의 여러 줄로 배치될 경우 불필요하게 지나치게 많은 수직 공간을 점유하여 하단 중요 리스트나 상세 내용이 화면 밖으로 밀려남.
  - 실행 흐름 배너 등에서 제공하는 소괄호 속 서브 설명(예: `(페르소나)`, `(원자 기능)`)이 좁은 뷰포트에서 표시되면 글자가 밀려 한 글자씩 개행되는 현상이 일어남.
* **해결책**:
  - `StatCard` 컨테이너에는 모바일 뷰포트에서 가로 한 줄에 나열될 수 있도록 `flex overflow-x-auto flex-nowrap scrollbar-none`을 적용하고, 개별 카드에 `min-w-[120px] flex-1 shrink-0`을 선언하여 레이아웃 뭉개짐이나 세로 2중 배치를 차단한다.
  - 가로가 좁은 모바일(sm 미만)에서는 소괄호 안의 불필요한 메타/서브 텍스트 정보들을 `@media` 또는 Tailwind의 `hidden sm:inline` 클래스를 조합하여 완전히 숨기도록 마크업을 정비한다.
