## 정의

세컨 브레인에 구조(Structure)와 인덱스를 부여하여, **에이전트가 필요할 때 필요한 컨텍스트만 가져올 수 있게** 만드는 능력. "다 담는 것"이 아닌 "잘 찾게 만드는 것"이 핵심.

> "컨텍스트를 필요할 때 필요한 만큼만 가져오게 만드는 능력" — 하재상 (실밸개발자)

## 문제 의식

### "다 담으면 되지 않나?"의 함정

신입에게 위키 5,000 페이지를 던져주면 위키가 없는 것과 같다 — 에이전트도 동일하다:
- 컨텍스트 양이 많을수록 **컨텍스트 노이즈** 발생
- 에이전트가 헷갈리고 느려지고 퀄리티 저하
- 불필요한 컨텍스트 비용 + 응답 속도 저하 + 정확도 하락

### 컨텍스트 윈도우의 현실

모델의 컨텍스트 윈도우는 커지고 있지만, 더 크다고 반드시 좋은 것은 아니다. "모래사장에서 바늘 찾기" 문제는 크기가 커져도 해결되지 않는다.

## 구현 방법: 인덱싱 기반 3단계

1. **수집 (Collect)**: 모든 정보를 일단 한 곳에 모은다. 코드 외부의 암묵지(암묵지, 팀 룰, 비즈니스 맥락 등)
2. **구조화 (Structure)**: 모듈·주제·서비스 단위로 잘게 쪼갠다. LM Wiki(Karpathy)처럼 마크다운 파일 단위
3. **인덱싱 (Index)**: 각 조각이 "어떤 질문에 답하는지", "어떤 모듈에 속하는지" 메타데이터 부여

에이전트가 일하다가 "결제 모듈이 필요하다"고 판단하면, 전체를 들고 다니는게 아니라 그 조각만 가져온다.

## 실제 사례

Meta 팀 내 사례 (하재상 발표):
- 기존: 복잡한 작업에 컨텍스트를 모두 주입 → **2시간** 소요
- 개선: 컨텍스트 인텔리전스 적용 (인덱싱) → **30분** 으로 단축 (4배 향상)
- 같은 모델, 같은 도구, 같은 프롬프트 — 컨텍스트 구조만 바꿨음

## 온톨로지와의 관계

컨텍스트 인텔리전스는 **온톨로지**의 실천적 구현:
- 온톨로지: 정보의 개념과 관계성을 설명하는 역학 (엔티티·릴레이션십)
- 컨텍스트 인텔리전스: 그 온톨로지를 에이전트가 효율적으로 활용할 수 있도록 인덱싱하는 것
- 인베딩, 인덱싱 모두 온톨로지의 하위 영역
