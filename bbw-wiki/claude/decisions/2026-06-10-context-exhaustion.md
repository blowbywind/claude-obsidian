# 컨텍스트 소진 원인 분석 (2026-06-09 세션)

## 증상

세션 중 "This session is being continued from a previous conversation that ran out of context." 메시지와 함께 대화 맥락이 요약문으로 대체됨.

## 원인 (기여도 순)

### 1위 — `@파일멘션`으로 대형 파일 직접 로드
`@prototype/index.html`을 메시지에 붙이면 Claude Code가 파일 전체를 컨텍스트에 주입한다.
5,383줄 파일 ≈ 15~20k 토큰. 이미 147k가 누적된 상태에서 임계값을 돌파시켰다.

### 2위 — 세션 6시간 이상 유지로 도구 결과 누적
14:32~21:13 = 6시간 40분 단일 세션. 모든 Bash 결과·파일 읽기·Write 완료 메시지가 컨텍스트에 쌓임.
전체 448턴 중 컨텍스트 100k+ 구간이 214턴 (전체의 48%).

### 3위 — 모듈화 작업 중 대형 파일 반복 읽기
5,383줄 파일을 CSS/JS 추출을 위해 여러 청크로 나눠 읽음.
15:20~15:24 사이 4분 만에 147k → 162k (+15k) 증가.

### 4위 — `autoCompactThreshold: 0.8` 설정
200k 윈도우의 80% = **160k 토큰**이 자동 압축 기준.
162k 돌파 시점부터 압축 대상이 됐고, 21:15에 실제 압축 발동 (167k → 39k).

### 5위 — SessionStart 훅 프로젝트 노트 전문 주입 (이미 개선됨)
세션 시작마다 `hnedu_erp.md` 전체가 `additionalContext`로 주입됐음.
→ 2026-06-10 INDEX.md 경량 주입 방식으로 개선 완료.

## 재발 방지 규칙

1. **5k줄 이상 파일 대상 작업 시작 전 새 세션 열기**
2. **`@파일멘션` 대신 경로 텍스트로 언급** — Claude Code가 자동 로드하지 않음
3. 긴 세션에서 컨텍스트가 100k 이상 누적됐다고 느껴지면 `/compact` 실행 후 계속
4. `autoCompactThreshold`를 0.6으로 낮추면 더 일찍 압축 (맥락 손실은 증가)
