## 1. 핵심 요약 (3줄)

1인 기업 대표 **김요일**이 **헤르메스(Hermes) 5명 + Claude Code 5명 = 10명의 AI 직원 팀**을 실제 운영하는 방법을 공개. 핵심은 ① 플랫폼별 역할 분리(헤르메스=에이전시, Claude Code=인하우스), ② 크론잡 야간 자율 학습 루프, ③ 옵시디언 위키로 10명 에이전트 간 맥락 공유. 어떤 AI 도구(Codex, Claude, Gemini)를 쓰든 위키만 있으면 즉시 맥락 연결이 가능해 도구 종속성을 제거한다.

## 3. 헤르메스(Hermes) 에이전트 — 기술 스택

### 정체
- **개발사**: Nous Research
- **출시**: 2026년 2월, GitHub 18,800+ stars
- **[OpenClaw](https://openclaw.ai/)와 유사한 로컬 에이전트** ✅ (자막 "오픈 클로" = OpenClaw 확인)
  - OpenClaw: 2026년 1월 출시 오픈소스 로컬 AI 에이전트, Telegram·Slack 등 22개 채널 지원
  - 헤르메스도 동일 콘셉트 — 로컬 설치 후 메시징 채널 연결
- "사람이 직접 컴퓨터를 조작하는 대신 컴퓨터가 대신 작업을 수행하는 소프트웨어"
- **여러 AI 도구들을 연결해서 실행시키는 작업 관리자** 개념
- 연결 가능 AI: Codex, Claude, Gemini 등 (v0.14.0 기준 22개 플랫폼 지원)

### 현재 연결 AI
- **OpenAI Codex CLI** ✅ — "토큰 사용량이 넉넉해서 안정적으로 사용"
  - 2026년 4월 토큰 기반 과금 전환 (5시간 롤링 윈도우)
  - 실사용 비용: $100–200/월 (파워유저 기준)
- 텔레그램 채널로 연결 (Slack도 가능, 1인 기업이라 가벼운 텔레그램 선택)

### 헤르메스 선택 이유 (5가지)
| # | 기능 | 설명 |
|---|---|---|
| 1 | 모바일 원격 실행 | 언제 어디서나 텔레그램으로 에이전트 실행 |
| 2 | 멀티 에이전트 무한 증식 | 고유 ID 개별 에이전트 생성 (세션 복제 아님) |
| 3 | 크론잡 | 예약 작업 — 정해진 시간에 루틴 자율 수행 |
| 4 | 로컬 데이터 접근 + 비동기 | 외부에서 로컬 파일 요청 → 완료 시 텔레그램 알림 |
| 5 | 장기 기억 + 학습 루프 | 한번 말한 것 영구 기억, 업무할수록 스스로 성장 |

### 설치 방법 (영상 직접 안내)
1. 구글 "헤르메스 에이전트" 검색 → 공식 홈페이지
2. 데스크톱 앱 설치
3. 앱 안에서 텔레그램 등 채널 연결
4. 세팅 방법: Claude Code 또는 Codex에게 명령
   - `"헤르메스 에이전트 설치했는데 GPT-5 모델로 세팅해줘"`
   - `"Claude면 Opus 4.8로 연결해줘"`
5. 대화하면서 에이전트 프로필 분기

## 4. 팀 구조 — 10명 AI 직원 상세

### 4-1. 헤르메스 에이전트 5명 (텔레그램, 야간·상시 담당)

회사명: **린네이티브(Lean Native)**

| 에이전트 | 역할 | 특이사항 |
|---|---|---|
| **효율이 (효1)** | 개발 + 취합·보고 모더레이터 (오른팔) | 실리콘밸리 논문·AI 뉴스·Reddit 야간 학습 |
| **효리 (효2)** | 디자인 (웹·앱 UI, PPT 슬라이드) | Dribbble 등 UI 레퍼런스 + OpenDesign 실습 |
| **효삼이 (효3)** | 자동화 + 효1 개발 서포트·검증 | **Claude Code로 연결** (다른 에이전트와 차별) |
| **효나 (효4)** | 콘텐츠 (이미지·영상, 카드뉴스, SNS, 유튜브 크롤링) | - |
| **효정이 (효5)** | 강의 보조 (리서치, 슬라이드, 커뮤니티, 일정 관리) | - |

### 4-2. Claude Code 에이전트 5명 (주간 업무 담당)

회사명: **린 프로젝트**

| 에이전트 | 역할 |
|---|---|
| **시원 (C1)** | 오케스트레이터 — 다른 에이전트에 업무 지시 후 최종 보고 |
| **C2, C3, 신하** | Plan 모드 기획, 스킬 제작, 연결 작업 |

### 4-3. 분리 이유
> "저 사람들도 폴더가 많아지면 찾기 어려워지는 것처럼, 에이전트들도 집중할 수 있는 환경을 만들어 주기 위해서"

- **헤르메스 = 에이전시** (외주 전문가 집단)
- **Claude Code = 인하우스** (내부 직원)
- 주간 업무 중 헤르메스에게 여러 요청으로 혼선 주지 않기 위함

## 5. 야간 자율 학습 루프 — 상세 설계

### 핵심 철학
> "저희가 자는 시간을 이용하는 겁니다"

### 준비 사항: 행동 기준 규칙 (CLAUDE.md 동일 개념)
- 에이전트마다 **해야 할 것 / 하지 말아야 할 것** 사전 약속
- `"클로드 MD처럼 행동 기준이 되는 규칙을 헤르메스에게도 적용"`

### 에이전트별 학습 설계

**효율이 (개발)**
```
학습 대상: 실리콘밸리 개발자 논문·학술 자료, AI 뉴스, Reddit, AI 블로그·커뮤니티
학습 깊이: 1~10 중 숫자로 설정
결과: 기상 시 엄청난 학습을 한 상태
```

**효리 (디자인)**
```
학습 대상:
  - Dribbble, Awwwards, Mobbin, Godly 등 UI 레퍼런스 사이트 주기적 탐색
  - 감각적인 기업·브랜드의 공개 디자인 시스템
실습:
  - OpenDesign (Claude Design 로컬화 오픈소스) CLI 연결
  - 레퍼런스 전달 → "95% 이상 똑같이 만들 때까지 무한 루프" → 취침
```

### 메모리 과부하 방지 (핵심 발견)
> "그 방대한 자료들을 전부 저장하면 메모리가 터져버리고 에이전트가 멍청해집니다"

해결책 — **옵시디언 위키화 3규칙** (못 박아두는 규칙):
```
1. 분석·학습이 끝나면 반드시 옵시디언 위키화
2. 메모리는 항상 최대 효율 유지
3. 관련 업무 시 키워드로 옵시디언 검색해서 참조
```

## 6. 맥락 공유 시스템 — 옵시디언 위키

### 왜 옵시디언인가
- 10명 에이전트가 **모든 맥락 공유** → "같은 회사 일원으로 하나의 목표를 향해 일함"
- **도구 종속성 제거**: Codex든 Claude Code든 Gemini든 위키만 있으면 맥락 즉시 연결
  > "어떤 도구를 사용하든 이 위키만 있으면 하던 작업을 바로 이어서 진행할 수 있고, 일일이 업무에 대해 설명을 할 필요가 없어집니다"

### 효과
- 헤르메스 5명 ↔ Claude Code 5명 간 지식·맥락 실시간 공유
- "진정한 에이전틱 엔지니어링"이라고 정의

## 7. 에이전트 간 통신 — Session Send

### Session Send = Claude Code Agent Teams ✅
Claude Code의 **Agent Teams** 기능 (v2.1.80+ 공식 지원):
- 리드 에이전트가 팀원 에이전트에게 업무 지시 → 각자 독립 컨텍스트에서 작업 → 결과 리드에게 보고
- 통신 방식: **공유 파일(디스크) 기반** (에이전트끼리 직접 소켓 통신이 아닌 파일 읽기/쓰기)
- Direct Message(1:1) + Broadcast(전체) 모두 지원
- 팀원은 CLAUDE.md, MCP, Skills 자동 로드 (리드의 대화 히스토리는 미공유)

### 3시간마다 자동 커밋 크론잡
```
목적: 업무 중 커밋 누락 방지
동작: 3시간마다 자동 커밋 + 옵시디언 저장
효과: 본인은 작업에만 집중
```

## 9. AI 네이티브 ERP 구상

옵시디언 위키를 기존 ERP에 통합하면 "전 직원이 나를 닮은 에이전트를 보조 직원으로 사용":

| 기능 | 내용 |
|---|---|
| 대시보드 | 모든 업무 한 눈에 |
| 태스크 뷰 | 회사 세부 일정 확인 |
| 메신저 | 전 직원 + 에이전트 통합 대화 |
| 에이전트 현황 | 예약 작업 모니터링 |
| 채널 연결 | 외부 흐름 원클릭 연결 |
| 스킬 인벤토리 | 사용 가능한 스킬·플러그인 목록 |
| 토큰 대시보드 | 작업별 토큰 사용량 분석 |

> 중소기업 AI 네이티브 도입 컨설팅도 제공 중 (합리적 비용)

## 10. 핵심 인사이트 (원문 발췌)

### "맥락 공유 시스템의 힘 = 진정한 에이전틱 엔지니어링"
> "저는 코덱스든 클로드 코드든 제미나이든 어떤 도구를 사용하든 이 위키만 있으면 하던 작업을 바로 이어서 진행할 수가 있고 일일이 업무에 대해 설명을 할 필요가 없어지는 겁니다."

### "개발 과잉 영역"
> "AI든 에이전트든 개발 과잉 영역이 존재한다고 생각합니다. AI를 만든 사람도 이 정도까지 만들어야지 하고 만들지는 않았을 겁니다. 그렇기 때문에 발전 가능성이 더욱더 무한하고 활용 방법도 무한하다고 생각이 듭니다."

### 메모리 관리
> "방대한 자료들을 전부 저장하면 메모리가 터져버리고 에이전트가 멍청해집니다."
